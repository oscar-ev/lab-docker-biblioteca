    4
    Arquivo 1 de 8

    O banco de dados: init.sql

    Este arquivo cria as “planilhas” (tabelas) do banco: uma de usuários e uma de livros. Também cria o usuário admin com senha admin.

    Quer entender o código? (opcional)
    CREATE TABLE
    Cria uma tabela, que é como uma planilha: colunas fixas e uma linha por registro.
    INT AUTO_INCREMENT
    Número que o banco gera sozinho: 1, 2, 3…
    PRIMARY KEY
    A coluna que identifica cada linha. Não pode repetir.
    VARCHAR(150)
    Texto de até 150 letras.
    NOT NULL
    Campo obrigatório.
    INSERT INTO
    Adiciona uma linha na tabela: o admin e dois livros de exemplo.
    Só para estudo: sistemas de verdade nunca guardam a senha assim, em texto puro. Veja o desafio extra no último passo.

    6
    Arquivo 3 de 8

    O servidor web: app.py

    O coração do sistema. Ele decide o que acontece quando alguém faz login, cadastra ou exclui um livro. É o maior arquivo: copie com o botão, não à mão.

    Quer entender o código? (opcional)
    @app.route("/login")
    Um “endereço” do site. Quando alguém abre /login, a função logo abaixo é executada.
    GET e POST
    GET = abrir a página. POST = enviar o formulário.
    conectar()
    Abre a conexão com o MySQL usando usuário e senha que vêm do docker-compose.
    %s
    Espaço reservado para os valores. Protege contra o ataque chamado SQL Injection.
    session["usuario"]
    Faz o site “lembrar” que você já entrou.
    con.commit()
    Confirma a gravação no banco. Sem ele, nada é salvo.
    host="db"
    No Docker, o banco é encontrado pelo nome do serviço: db.

    Arquivo 8 de 8 · último!

    Juntando tudo: docker-compose.yml

    Diz ao Docker para ligar duas caixas: o banco (db) e o site (web), e como uma encontra a outra. Este fica fora das pastas, direto na raiz.

    Os espaços importam: neste tipo de arquivo (YAML), o recuo no começo das linhas faz parte do código. Por isso, cole sem mexer.
    Quer entender o código? (opcional)
    services
    A lista de caixas: db e web.
    image: mysql:8.0
    Usa o MySQL pronto, baixado da internet.
    environment
    Configurações: nome do banco, usuário e senha.
    healthcheck
    Teste que avisa quando o banco está pronto.
    depends_on
    O site só liga depois que o banco estiver pronto.
    ports "5000:5000"
    Porta do seu computador : porta dentro da caixa.

    Teste rápido: se você trocar para "8080:5000", onde o site vai abrir?

    Ajuda

    Deu erro? E desafios extras

    Clique no problema que aconteceu com você para ver a solução.

    “port is already allocated” (porta em uso)

    Outro programa já usa a porta 5000. No docker-compose.yml, troque "5000:5000" por "5001:5000", rode de novo e abra localhost:5001.

    “docker não é reconhecido” ou “Cannot connect to the Docker daemon”

    O Docker Desktop está fechado ou ainda iniciando. Abra, espere aparecer Engine running e tente de novo.

    “no configuration file provided: not found”

    O terminal não está na pasta biblioteca, ou o arquivo não se chama exatamente docker-compose.yml. Volte ao passo 3 e abra a pasta certa no VS Code.

    “TemplateNotFound: login.html”

    A pasta das páginas precisa ser app/templates. Compare sua lateral do VS Code com a árvore dos passos 7 a 9.

    Mudei o app.py e o site não mudou

    Pare com Ctrl + C e rode de novo docker compose up --build. Confira também se salvou o arquivo (Ctrl + S).

    Mudei o init.sql e nada mudou no banco

    Esse arquivo só roda na primeira vez. Para apagar o banco e começar do zero (perde os livros cadastrados):

    Acentos aparecem estranhos (ex.: “AluÃ­sio”)

    Desafios extras

    1. Nova coluna: adicione genero VARCHAR(50) na tabela e um campo no formulário.
    2. Busca: crie um campo de pesquisa usando WHERE titulo LIKE %s.
    3. Editar livro: crie uma rota que use UPDATE livros SET … WHERE id = %s.
    4. Senha segura: use generate_password_hash e check_password_hash do werkzeug.security.
    5. phpMyAdmin: adicione um terceiro serviço no compose com a imagem phpmyadmin na porta 8080.
